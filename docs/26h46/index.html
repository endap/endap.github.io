JavaScript booleans are a primitive type that can be used directly without first explicitly created as an object 1. The booleans can only have value true or false or obtain value converted from string 2. There are six falsy value and everything else is truthy to use 3, that can be converted to booleans 4. A common use of this primitive type is as flag, that can be toggled in several ways 5. In this post it is used as flag in showing or not showing comments.

sorting

Bubble sort is an algorithm chosen when simplicity is favoured over efficiency 6. It compares elements and swap values for a condition until all elements are processed 7, so that elements tend to be in order at each step like bubble 8 with available C++ example 9.

A function represented bubble sort algorithm is written as follows.

function bubbleSort(x) {
  const y = T1D.clone(x);
  const n = T1D.len(y);
  for(let i = 0; i < n - 1; i++) {
    for(let j = i + 1; j < n; j++) {
      if(y[i] > y[j]) {
        const t = y[i];
        y[i] = y[j];
        y[j] = t;
      }
    }
  }
  return y;
}

info

In developing program sometime we need to display info at certain line to assure that a logic works. For example how to monitor whether at each step the algorithm work and the numbers order are rearranged until they are in ascending order? Previous output show the initial and final order of the numbers, which does not give any information above the sub-process in the function. Compare it with following output.

Now you can see that at each outter iteration the state of numbers are shown and also whether the swap is required or not. You can trace from the messages elements position change.

code

To get previous results the code is as follows.

import { Tensor1D as T1D } from "endap";
import { RandNum as RNU } from "endap";
import { Console as CLI } from "endap";

const consoles = CLI.create("200px");
const cnt = document.getElementById("cnt2");
cnt.append(consoles.el);

function bubbleSort(x, processInfo) {
  const y = T1D.clone(x);
  const n = T1D.len(y);
  for(let i = 0; i < n - 1; i++) {
    if(processInfo) {
      consoles.log("\ncurrent state is ", "")
      consoles.log(y);
    }
    
    for(let j = i + 1; j < n; j++) {
      let msg;
      if(y[i] > y[j]) {
        msg = "  swap element " + i + " with element " + j;
        const t = y[i];
        y[i] = y[j];
        y[j] = t;
      } else {
        msg = "  no swap"
      }
      if(processInfo) {
        consoles.log(msg);
      }
    }
  }
  return y;
}

let subProcessInfo = true;

const min = 10;
const max = 90
const n = 10;
const z1 = RNU.randIntN(min, max, n);
consoles.log("Before sort: ", "");
consoles.log(z1);

const z2 = bubbleSort(z1, subProcessInfo);
consoles.log();

consoles.log("After sort: ", "");
consoles.log(z2);

First output, that shows only initial and final numbers orders, is obtained with

let subProcessInfo = false;

while the second output is using

let subProcessInfo = true;

where the flag subProcessInfo is passed to the bubbleSort(x, processInfo) function

which is quite different compared to the formerly given one. Notice that it has now second argument processInfo for the flag to determine whether the info about sub-process should be display or not. This information is very usefull in debuging but can be very annoying while running the program. To avoid such messy output a flag subProcessInfo is defined. In the real project you can separate the development source code and the one for delivery. It is better to strip out those the make the code concise, but keep the main one for future maintenance. There are pros and cons about this approach 10.
